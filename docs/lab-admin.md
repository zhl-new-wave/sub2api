# 管理员使用指南

## 权限分工

使用个人管理员账号登录 <https://api.zhllabhub.com/login>。普通成员只需要用户权限和个人下游 Key。不要用管理员密码、管理接口密钥或上游账号凭据代替成员 Key。

新增管理员只授予实际维护者；管理员可以接触成员、计量和上游授权信息。成员离开实验室时撤销其 Key 并禁用账号，保留必要审计记录。

## 建立可用的账号链路

按「上游账号 → 分组 → 成员 → API Key → 调用记录」依次核对：

1. **上游账号**：在账号管理选择对应供应商及 OAuth/API Key 类型，由账号持有人完成授权。确认启用状态、可调度状态、并发和授权有效性；不要把上游 token 发给成员。
2. **分组**：为 Codex 建立 OpenAI 兼容分组，绑定合适的账号，核对模型映射、模型白名单、倍率和并发。新增模型前做一次低成本验证。
3. **成员**：为每个人创建普通用户，设置初始余额/订阅权益、并发和允许分组。将初始密码通过私有渠道交给本人修改。
4. **API Key**：让成员在自己的账号创建 Key，或为该成员创建独立 Key。核对所属用户、分组、额度、有效期和 IP 访问限制。
5. **验收**：用成员权限执行一次[只读 Codex 试跑](lab-users.md#codex-只读试跑)，在用量页确认归属、模型与扣额。

现有试用 Key 的配额和有效期未因迁移或建仓库自动延长；部分最初设置为 2026-11-04 到期，请在 Key 管理页按实际使用计划调整。

## 调度与配额

- 从少量账号和保守并发开始；提高站内余额不会提高订阅账号的真实上游容量。
- 用户并发、Key 限额、分组限制及上游账号容量需要分别核对。避免 7–8 人同时跑批量任务把号池压满。
- 定期检查授权失效、429/401、账号冷却和错误率。不要通过不断重试掩盖持续故障。
- 缓存命中取决于上游及路由，不能按“同账号必定命中”估算成本或吞吐。
- 计量、定价和余额属于网关账本。对外报销或论文实验时另行记录实际采购、模型版本、请求参数与处理链路。

## 扩展其他供应商

先核对该版本支持的上游协议和账号类型，再新建独立账号/分组。官方 API、云平台 API 和第三方中转分别管理凭据和预算，避免把实验对比混在同一个自动换源分组里。

目前部署的出站域名白名单仅覆盖 OpenAI。新供应商接入除了网页设置，还需要由服务器管理员更新 Compose 的 `SECURITY_URL_ALLOWLIST_UPSTREAM_HOSTS` 并重建应用；继续禁止内网目标和不必要的明文 HTTP。仅添加网页账号而未更新白名单可能无法使用。

## 网页与服务配置

站点名为 **ZHL Lab API Hub**，前端地址与 API 展示地址均配置为 `https://api.zhllabhub.com`，客户端 API Base URL 加 `/v1`。公开注册、密码找回和其他尚未配置完整的入口应保持当前受控状态；不要为方便测试临时开放管理权限。

网关的 OAuth 授权、默认 instructions、请求字段过滤和工具行为由上游源码及客户端共同决定。普通 API 与 Codex 请求不能假设完全相同；做论文实验时保存客户端版本和关键参数，避免把网关转换结果称为未经处理的官方 API。

## 日常检查与备份

服务、数据库、Caddy 和定时任务由服务器运维工具管理，见[服务器运维说明](../deploy/digitalocean/README.md)。每天检查逻辑备份是否新鲜，并在 DigitalOcean 控制台核对自动快照；当前没有独立接收端自动副本。备份失败不会自动从聊天窗口通知管理员。

修改账号、模型映射、定价或重要设置前创建恢复点。通过网页或经过核对的管理接口操作，避免直接写 SQL。后台批量操作先在一个对象上验证，再扩大范围。

## 处理故障

1. 先区分 DNS/网络、HTTPS、网关鉴权、调度和上游错误，保留时间与请求 ID。
2. 服务端先执行 `sub2api-lab status`，再查看有针对性的日志。
3. 在网页核对用户、Key、分组、账号授权和剩余额度；检查是否出现模型映射误改。
4. 必要时暂停故障上游账号，确认替代账号的许可、能力和预算后再切换。
5. 记录操作与恢复时间；涉及升级/回退时按[维护流程](lab-maintenance.md)处理。

日志、后台导出和 OAuth token 都可能含敏感信息。分享问题时只提供脱敏的必要字段。
